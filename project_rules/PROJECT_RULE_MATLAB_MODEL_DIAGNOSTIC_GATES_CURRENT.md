# MATLAB 诊断与完整任务执行
更新：2026-09-07；替代旧 12 个小 gate 的强制交接顺序。

## 同一任务内的正常阶段
源/输入确认 → 外部 wrapper 或允许副本的修复 → 相关静态/合成检查 → 预算内科学执行 → 核心输出保存 → 诊断和报告。
这些是执行依赖，不是必须分开发单的门禁。允许合并授权，不能在前提失败时盲目运行。

## 保留的科学控制
原始 MATLAB 只读。确定入口、科学对象、配置、输出目录及合理时间/空间上限。
任务写清模型调用、内部迭代及重试预算；计数单位不能混用。每次实际科学 invocation 即使失败也计数；调用前失败与调用后失败分开记录。
不可变输入与源身份必须一致。不得擅改方程、KKT/边界、求解器、校准、容差、网格或迭代上限。

## 工程失败
任务覆盖的路径、绑定、类型、保存、诊断向量化故障由 Builder 修复并做相关检查，无需另外申请每一步。
已有核心产物时优先重做后处理。需重新调用模型时仅使用任务明确的剩余/重试预算；没有预算就暂停模型步骤并完成报告。
科学不收敛、质量不守恒或实质 parity 差异不能靠放宽标准处理。

## 验收
按实际对象检查 HJB/KFE、算子方向、质量/非负性、聚合、市场或外层收敛等适用项。单次首轮比较不要求验证不存在的冲击/IRF对象。
smoke、exit 0、成功绘图只支持对应工程行为。保护源身份和来源足够明确时不重复做全目录考古。
正式 Results 按已接受科学范围审阅；本规则不授权任何模型调用。
