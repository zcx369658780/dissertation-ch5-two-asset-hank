### 流程反思与实质改进
1. **早期任务过细**：为根目录建立、C/D映射和副本方案分拆过多子门/remote状态提交，使V0.0.5耗时与GitHub频次偏高。Owner曾提醒GitHub频繁中转可能触发平台安全审核，这属于Owner经验与风险提示，**不能断言本轮GitHub触发了新的审核**。调整为V1.2的“一个完整长任务、一个必要冻结点、集中验收、少GitHub提交”。
2. **概念混用**：Python/MATLAB程序已有本地及GitHub备份（Owner所述），新物理隔离卷不是常规代码备份的必要前提。可信可弃用 fixture 是全D2敌对Windows攻击实验的单独安全前置，不是所有科研编程、SOURCE_ONLY或合成测试的普遍阻塞。
3. **实现缺陷**：Windows \`DirEntry.stat\` 在Win3.11下身份字段虚零，比较器误报。B3修复采用真实句柄统一身份；未来应先做单个内存/普通文件聚焦回归再做全量长任务，避免安全策略因平台语义误判。
4. **治理同步边界**：动态 \`CURRENT.md\` 曾累加十余万字历史前缀，已保留历史固定提交并缩减为当前摘要；GitHub文档与原D工作树dirty不同源，不能以“对齐”名义覆盖本地科研原件。
5. **避免重复伪证明**：全普通字节匹配不证明全树时间点、ADS/ACL/外部链接或A16，模型Results仍FALSE。关闭版本不是科学PASS。
6. **不为几MB缓存冒险**：未明确引用关系、重新生成资格和准确删除清单时，即使B3有限备份通过，也保留原目录。把可选空间清理延至独立维护决策，避免拖慢投稿科研主线。
